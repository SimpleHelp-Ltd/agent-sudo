agent-sudo

Give a trusted agent temporary root access, without sharing your administrator password.

Install once. Grant access to an existing account when needed. Hand the agent its private token.

Ubuntu 24.04 / 26.04Linux amd64systemd

For administrators

Setup and use

1. Install machine-wide

curl -fsSL https://tools.simplehelp.io/agent-sudo/install.sh | sh

Run this in a terminal. The script downloads and checks the pinned package, then sudo requests your normal administrator authorization. There is no account-selection step. Look for Installed agent-sudo 1.0.2 before proceeding.

The package checksum is pinned in the HTTPS bootstrap; it detects corrupted or mismatched packages. It is not a signature or protection against a compromised download site.

2. Grant access

agent-sudo agent 10

Replace agent with an existing local non-root account and 10 with the number of minutes (1–1440). Any administrator whose sudo policy permits the grant operation can issue a grant.

agent-sudo agent     # Prompts for minutes; Enter selects 10
agent-sudo           # Enter selects your account and 10 minutes

For bare agent-sudo, the username defaults to the account running it and minutes defaults to 10. Press Enter to accept either default.

Sudo handles fresh administrator authentication. Passwordless administrator policies may not prompt. agent-sudo never receives or saves your administrator password.

3. Give the token privately to the agent

A successful grant prints one secret token. The account can use it immediately. Give that token privately to the intended agent; keep it out of recorded terminals, logs, command arguments and environment variables.

For a recipient whose username matches a command name, use agent-sudo grant --user USERNAME --minutes 10. The readable summary shows the account, local expiry time with timezone and revocation command. Detailed machine identity remains available in status output. Redirected stdout contains only the token; explanations go to stderr. A lost token cannot be recovered; revoke that grant and issue a new one.

Check and revoke

agent-sudo admin list
agent-sudo admin revoke GRANT-ID
agent-sudo revoke all

These commands use normal fresh sudo authorization. agent-sudo revoke all revokes every grant you issued, across all recipient accounts. Other administrators’ grants stay valid. Run it without a leading sudo to keep your own issuer identity. Revocation stops new commands; already admitted work can continue.

Upgrade or remove

Run the same installation command to install the current release or revalidate a changed sudo policy. Installation and upgrades invalidate all previous grants, including when upgrading from 0.1.0.

sudo /usr/local/libexec/agent-sudo-helper uninstall

Removal disables access and removes managed files. Keep an independent administrator session available.

For agents

Using granted access

Run agent-sudo --help (or agent-sudo -h) for the complete terminal guide.

Receive your token, then run a command

agent-sudo run -- /usr/bin/id </dev/null

Paste the token into the hidden Access token (hidden): prompt. You never need the administrator’s password. Use an absolute executable path. Redirect stdin for commands that need no input.

agent-sudo run -- /bin/cat < input.bin > output.bin

Binary stdin, stdout and stderr are supported. This release has no PTY; terminal editors and other full-screen terminal applications are unsupported.

Automation through a descriptor

agent-sudo run --key-fd 3 -- /usr/bin/id </dev/null

Your trusted launcher must supply descriptor 3 already open. It must contain the token plus a newline or EOF. --key-fd must be at least 3 and is separate from command stdin. Do not put the token itself in the command, environment or logs. The operator guide includes a complete Python/SSH example and separate --result-fd output for reliable automation.

Check access or give it up

agent-sudo status
agent-sudo revoke GRANT-ID
agent-sudo revoke --all

These show metadata or revoke grants issued to your account without reading a token. revoke --all gives up all grants you received; the administrator’s revoke all instead revokes grants they issued. After the last grant expires or is revoked, recipient operations are denied. Ask an administrator for a new grant; there is no automatic renewal.

Full root authority

This grants arbitrary root commands to an account you trust. Expiry, revocation and reboot prevent new admissions; already admitted root processes can outlive expiry and may establish persistent access. Tokens are bound to the account, machine and current boot. Processes sharing a UID are not strongly isolated.
