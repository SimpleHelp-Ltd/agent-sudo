For administrators

Set up in three steps

Install once per machine, then grant time-limited access to an existing account whenever an agent needs it.

  1. Install machine-wide

    curl -fsSL https://tools.simplehelp.io/agent-sudo/install.sh | sh

    Run it in a terminal and approve the normal sudo prompt. You’re done when you see Installed agent-sudo 1.0.3.

    The pinned package checksum detects corrupted or mismatched downloads. It is not a signature and does not protect against a compromised download site.

  2. Grant access

    agent-sudo agent 10

    Grants the existing non-root account agent access for 10 minutes (1–1440). Sudo asks you to authenticate; agent-sudo never sees or saves your password.

    Leave out values to be prompted: agent-sudo agent asks for minutes; agent-sudo also asks for the account. Press Enter for the defaults—your own account and 10 minutes.

  3. Paste the line to your agent

    agent-sudo prints “Copy and paste this line to your agent:” followed by:

    see: https://simple-help.com/tools/agent-sudo | TOKEN

    Send it privately to the intended agent. Keep it out of shared or recorded terminals, logs, command arguments and environment variables. A lost token can’t be recovered: revoke it and grant again.

Check and revoke

CommandWhat it does
agent-sudo admin listShow grants
agent-sudo admin revoke GRANT-IDRevoke one grant
agent-sudo revoke allRevoke every grant you issued, for all accounts

Each asks for sudo authentication. Run them without a leading sudo so your identity is kept. Other administrators’ grants stay valid. Revocation blocks new commands; work already running can continue.

Upgrade or remove

To upgrade, run the install command again. This invalidates all existing grants, so issue fresh ones afterwards.

To remove:

sudo /usr/local/libexec/agent-sudo-helper uninstall

Removal disables access and deletes managed files. Keep a separate administrator session open while upgrading or removing.

More details for administrators
  • Any administrator whose sudo policy permits the grant operation can issue grants. Passwordless sudo policies may not prompt.
  • If the recipient’s username matches a command name, use agent-sudo grant --user USERNAME --minutes 10.
  • The grant summary shows the account, local expiry time with timezone and the revoke command. agent-sudo admin list shows full machine details.
  • Redirected stdout contains only the token, for scripts; explanations go to stderr.
  • New tokens are 67 characters (v2) with the same 256-bit secret strength. Older v1 tokens are still accepted.
  • Re-running the installer also revalidates a changed sudo policy. Upgrades from any earlier release, including 0.1.0, invalidate grants.
  • Revoke grants before deleting or reusing a recipient account.

This is full root access

  • Only grant access to an account and agent you trust: it can run any command as root.
  • Expiry, revocation and reboot stop new commands. Root processes already started can outlive expiry and could set up persistent access.
  • Tokens only work for the granted account, on this machine, until the next reboot. Processes sharing that account are not strongly isolated from each other.

For agents

Using a granted token

You received a line like see: https://simple-help.com/tools/agent-sudo | TOKEN. The part after | is your private token. Don’t echo, log or store it. Run agent-sudo --help for the full terminal guide.

  1. Run a root command

    agent-sudo run -- /usr/bin/id </dev/null

    Enter the token at the hidden Access token (hidden): prompt. You never need the administrator’s password.

    • Use an absolute path to the executable.
    • Redirect stdin (</dev/null) when the command needs no input.
    • Binary stdin, stdout and stderr work: agent-sudo run -- /bin/cat < in.bin > out.bin
    • There is no PTY, so editors and other full-screen terminal programs won’t work.

  2. Automate without a prompt

    agent-sudo run --key-fd 3 -- /usr/bin/id </dev/null

    Your trusted launcher supplies the token on an already open descriptor (3 or higher), ending with a newline or EOF. This is separate from the command’s stdin. Never put the token in the command line, environment or logs.

    The operator guide has a full Python/SSH example and --result-fd for reliable result reporting.

  3. Check or give up access

    CommandWhat it does
    agent-sudo statusShow your grants and expiry
    agent-sudo revoke GRANT-IDGive up one grant
    agent-sudo revoke --allGive up every grant issued to your account

    These don’t need the token and only affect grants issued to your account. (An administrator’s revoke all instead revokes the grants they issued.) Grants don’t renew: when the last one expires or is revoked, ask an administrator for a new one.

How 1.0.3 was tested

Tested with the installed production binaries in disposable QEMU/KVM VMs: Ubuntu 24.04.5 with sudo 1.9.15p5, and Ubuntu 26.04.1 with sudo-rs 0.2.13. It passed 230 installed-VM checks and 38 public installation checks. The validation evidence lists exact hashes, checks and simulated failures.

Only the documented local sudo policies are supported. There has been no independent audit; other platforms and exhaustive power-loss recovery are untested.

Earlier immutable downloads (0.1.0, 0.2.0, 1.0.0 and 1.0.1) remain available at their original URLs.
