agent-sudo

Give a trusted agent temporary permission to run root commands, without sharing your administrator password.

A local Linux CLI with short-lived, revocable tokens. No network service. Tested in disposable Ubuntu VMs; Loom testing is pending.

Install the preview

sh -c 'set -e; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL https://tools.simplehelp.io/agent-sudo/install.sh -o "$f"; sh "$f"'

Run in an administrator’s terminal on the target machine. You’ll be asked for the existing account to enroll, then normal sudo authentication. Choose the agent’s account explicitly; it may be different from your administrator account. The installer does not create accounts.

Ubuntu 24.04 / 26.04 · Linux amd64 · systemd · curl required. Validated with traditional sudo 1.9.15p5 and sudo-rs 0.2.13. Unsupported sudo policies fail closed. Keep an independent administrator session open.

What this command downloads and verifies

The command saves the bootstrap to a temporary file and runs it with terminal input available for prompts. The bootstrap downloads the pinned 0.1.0 package over HTTPS, verifies its SHA-256, then invokes the package’s existing offline installer through sudo. When started from a normal administrator account, downloads and verification run without root; only the verified package installer is invoked through sudo.

The bootstrap and checksum depend on your trust in this HTTPS site. Checksums detect changed or corrupt bytes; they are not signatures and do not prove authenticity if the site is compromised.

Inspect the bootstrap · Offline installation and recovery

Full root authority, for a trusted account

This is not a sandbox. An admitted command can do anything root can do, including establish persistent access. Expiry and revocation block new commands; already admitted root processes can outlive expiry. Keep tokens out of arguments, environment variables, shell history and logs. Avoid recorded terminal sessions when issuing a token.

From installation to a root command

1 · Administrator

Enroll the intended account

The install command above prompts for the existing recipient. Replace agent in the examples below with that account. For several recipients, download the bootstrap and provide the complete list:

curl -fsSLo agent-sudo-install.sh https://tools.simplehelp.io/agent-sudo/install.sh
sh agent-sudo-install.sh --user agent --user second-agent

Every installation replaces the entire enrollment list and invalidates existing grants. Remove the downloaded bootstrap afterward if desired.

2 · Administrator

Issue a grant

agent-sudo grant --user agent --minutes 60

Normal sudo authorization is requested afresh; your administrator password stays with sudo. Stdout contains one secret token line. Stderr shows its grant ID, recipient, machine identity, expiry and revocation instructions. Deliver the token privately to the recipient.

Run agent-sudo without arguments for interactive recipient/duration prompts. Duration: 1–1440 minutes, default 60. Grants are bound to the recipient account, host and boot.

3 · Enrolled recipient

Use the grant

agent-sudo run -- /usr/bin/id </dev/null

Paste the token into the hidden prompt. Use an absolute executable path. Command stdin remains separate; binary input and output are supported. There is no PTY, so full-screen editors and interactive terminal applications are unsupported.

agent-sudo run -- /bin/cat < input.bin > output.bin

Automation can supply a token via --key-fd N (N ≥ 3), never argv or environment. See the operator guide for SSH delivery and a separate --result-fd for unambiguous execution results.

4 · Check and revoke

Control future admissions

# Recipient: metadata only, no token needed
agent-sudo status
agent-sudo revoke GRANT-ID
agent-sudo revoke --all

# Administrator: normal sudo authorization
agent-sudo admin list
agent-sudo admin revoke GRANT-ID

Expiry, revocation and reboot prevent future uses. They do not stop admitted work or revoke independent sudo access.

Upgrade or change recipients

Run the installation command again and supply the complete enrollment list. It currently installs preview 0.1.0; future releases will update the pinned version after validation.

All grants become unusable, including during rollback. Sudo-policy changes require administrator reinstallation/revalidation. Modified managed files are refused.

Remove

sudo /usr/local/libexec/agent-sudo-helper uninstall

Disables admissions and removes managed files. Unrelated sudo permissions remain. A disabled root-only lock tombstone is retained for safe ordering with old helpers.

Removal cannot undo root persistence. See the independent recovery procedure if managed files were modified.
