# agent-sudo 1.0.0 public installation validation

2026-11-02. Release 1.0. Loom 0.2.0 root-command smoke passed; its expiry recheck is pending. 1.0 itself is tested in disposable VMs. No development-host installation, Loom changes, GitHub push or GitHub release.

**36 public installation checks passed**, 18 on Ubuntu 24.04.5 with sudo 1.9.15p5 and 18 on Ubuntu 26.04.1 with sudo-rs 0.2.13, in disposable QEMU/KVM VMs. These are additional to the 230 installed-binary checks in 1.0.0-VALIDATION.md.

## Actual public HTTPS and normal sudo

```sh
curl -fsSL https://tools.simplehelp.io/agent-sudo/install.sh | sh
```

The literal command above ran in each VM as the non-root humanadmin test account, with a real controlling terminal, cleared sudo cache and ordinary PAM password prompt. Installation asked for no recipient. The actual public bootstrap and package were downloaded over HTTPS and matched their pinned bytes. A second invocation reinstalled successfully. Actual public-installed binaries then issued positional grants to two previously unselected accounts, executed root commands through private token descriptors, reported status, revoked access and rejected reuse. Installed frontend/helper hashes matched the exact local production candidates. Removal completed cleanly.

Seven immutable downloads (package, source, archive checksum, aggregate checksums and three guides) were verified independently from their real public URLs. Original 0.1.0 and 0.2.0 assets were retained.

## Injected faults, separately identified

VM-local PATH shims simulated a failed bootstrap download, truncated bootstrap, failed package download, truncated package, corrupt package checksum and unsupported architecture. Root-controlled OS metadata simulated an unsupported OS. Old recipient installer options were rejected before changes. Each case preserved installed binaries, policy/configuration, manifest and units; no fault reached sudo, and temporary directories were cleaned.

Every one of the 2564 proper byte prefixes of the actual downloaded bootstrap ran through a shell under external-command marker shims, and none executed installation or other marked commands. The complete script was a positive control. Successful downloads/installation above use actual HTTPS, not these fault shims. These are not claims of induced production hosting failures.

The required short pipeline can return shell status zero when curl fails before producing any bytes: sh executes empty input. Curl still reports the download error and no installation begins. Confirm the final `Installed agent-sudo 1.0.0` message or `agent-sudo --version` before proceeding. Complete-bootstrap package failures return nonzero.

## Page validation and limits

The page uses the actual SimpleHelp logo, Ubuntu headings/navigation, Noto Sans body, inspected purple/blue palette, white surfaces and the solid purple primary button. Local browser checks cover 375/768/1280 px layouts, loaded brand fonts, keyboard focus/activation, exact copy text and clipboard-denial fallback. Live page, clipboard and MIME/link verification are recorded separately after page publication in docs/publication/1.0.0-browser-verification.json and the final publication receipts.

Platform support is limited to the documented Ubuntu amd64/systemd and sudo policies. No independent audit or exhaustive power-cut testing. Tokens must remain private; already admitted root processes may outlive expiry and establish persistence. Revoke before account deletion/reuse. Account names matching CLI command names use `agent-sudo grant --user USERNAME --minutes MINUTES`.
